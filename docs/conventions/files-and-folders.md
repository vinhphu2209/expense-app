# Files & Folders Conventions

> Related: [code style](code-style.md) · [database](database.md) · [documentation](documentation.md)

This document says **where every kind of file goes, what it is called, and what it must contain when created**. If a file you need doesn't fit any rule here, stop and propose a rule in your PR. Don't invent a location.

### 1.1 Ownership

| Path | Owner | Others may |
| --- | --- | --- |
| `supabase/**`, `src/lib/domain/**`, `src/server/**`, `src/app/api/**`, `src/lib/supabase/**`, `src/middleware.ts`, `src/env.ts` | Claude Code | Request changes in an issue or PR comment |
| `src/app/(app)/**`, `src/app/(auth)/**` pages/layouts, `src/components/**`, `src/hooks/**`, `public/**`, `src/app/manifest.ts`, service worker, `tests/e2e/**`, `docs/screens/**` | Antigravity | Request changes |
| **Definition files:** `AGENTS.md`, `CLAUDE.md`, `.claude/**`, `.agents/**`, `.github/**`, `docs/plan.md`, `docs/ai-workflow.md`, `docs/adr/**`, `docs/conventions/**`, `docs/operations/**` | Claude Code ([ADR-0016](../adr/0016-claude-code-maintains-definition-files.md)) | Antigravity: request changes ("Request for Claude Code: …"), never edit. Changes are called out in *Review focus* and summarised to Phú |
| `package.json`, lockfile, root config files | Shared | Any change explained in the PR's *Changes* section |

Security-sensitive code (`auth`, Supabase clients, middleware, `env.ts`) is owned by Claude Code, even when a UI task needs it.

## 2. Naming rules

| What | Rule | Example |
| --- | --- | --- |
| Folders | kebab-case | `month-close/`, `quick-add/` |
| TS/TSX files | kebab-case | `envelope-chips.tsx`, `parse-vnd.ts` |
| Next.js special files | Framework names, unchanged | `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`, `route.ts`, `[id]/`, `(app)/` |
| React components (export) | PascalCase, named export | `export function EnvelopeChips()` |
| Hooks | file `use-<name>.ts`, export `use<Name>` | `use-offline-queue.ts` → `useOfflineQueue` |
| Functions | camelCase, verb first | `parseVnd`, `rankEnvelopes`, `closeMonth` |
| Constants | `SCREAMING_SNAKE_CASE` for true constants | `MAX_AMOUNT_VND` |
| Types / interfaces | PascalCase, no `I` prefix | `Transaction`, `BudgetLine` |
| Zod schemas | PascalCase + `Schema` | `TransactionInputSchema` |
| Inferred types | Same name without `Schema` | `type TransactionInput = z.infer<typeof TransactionInputSchema>` |
| Server actions | verb + noun | `createTransaction`, `softDeleteTransaction` |
| Unit tests | next to the file: `<file>.test.ts` | `parse-vnd.test.ts` |
| E2E tests | `tests/e2e/<flow>.spec.ts` | `quick-add.spec.ts` |
| pgTAP tests | `supabase/tests/<NNN>_<topic>.test.sql` | `010_rls_transactions.test.sql` |
| Migrations | generated by CLI, snake_case name | `20261120093000_create_transactions.sql` |
| Docs | kebab-case `.md` | `ios-shortcuts.md` |
| Root meta files | UPPERCASE by convention | `README.md`, `CHANGELOG.md`, `AGENTS.md` |
| ADRs | `NNNN-<kebab-title>.md` | `0004-money-as-integer-vnd.md` |
| Screenshots | `docs/screens/<plan-id>-<screen>-<state>.png` | `P1-03-quick-add-empty.png` |
| Icons | `public/icons/icon-<size>.png`, `apple-touch-icon.png` | `icon-512.png` |
| Env vars | `SCREAMING_SNAKE_CASE`; `NEXT_PUBLIC_` **only** for values safe in the browser | `SUPABASE_SERVICE_ROLE_KEY` |

General rules:

- ASCII only in file and folder names. No spaces, no Vietnamese diacritics.
- No `utils2.ts`, `new-`, `-old`, `-final`, `temp` names. Git keeps history.
- One exported component per `.tsx` file (small private sub-components may stay in the same file).
- No barrel `index.ts` files except the **public API** of a domain module (`src/lib/domain/<module>/index.ts`) and `src/lib/domain/index.ts`.

## 3. Recipes: creating a new file

Each recipe lists **location → name → skeleton → checklist**. Agents must follow the recipe that matches the file they create.

### 3.1 Domain module (types + Zod + pure functions)

Owner: Claude Code. Location: `src/lib/domain/<module>/`.

```text
src/lib/domain/transactions/
├── schema.ts          # Zod schemas (input/output contracts)
├── types.ts           # Types not derived from Zod (rare)
├── <function>.ts      # One pure function (or a small family) per file
├── <function>.test.ts
└── index.ts           # Re-exports the public API only
```

```ts
// src/lib/domain/transactions/schema.ts
import { z } from "zod";
import { VndAmountSchema } from "../money";

export const TransactionInputSchema = z.object({
  type: z.enum(["expense", "income", "transfer"]),
  amount: VndAmountSchema,
  accountId: z.string().uuid(),
  envelopeId: z.string().uuid().nullable(),
  note: z.string().max(200).optional(),
  clientId: z.string().uuid(), // idempotency key
});

export type TransactionInput = z.infer<typeof TransactionInputSchema>;
```

Checklist:

- [ ] Pure: no I/O, no `Date.now()` (pass `now` as a parameter), no Supabase imports.
- [ ] Every exported function has a `*.test.ts` with edge cases listed in the issue plan.
- [ ] Exported from the module `index.ts`, and the module exported from `src/lib/domain/index.ts`.
- [ ] UI imports **only** from `@/lib/domain` (never deep paths).

### 3.2 Server Action

Owner: Claude Code. Location: `src/server/actions/<module>.ts`. One file per domain module.

```ts
// src/server/actions/transactions.ts
"use server";

import "server-only";
import { TransactionInputSchema, type TransactionInput } from "@/lib/domain";
import { createServerClient } from "@/lib/supabase/server";
import type { ActionResult } from "./types";

export async function createTransaction(input: TransactionInput): Promise<ActionResult<{ id: string }>> {
  const parsed = TransactionInputSchema.safeParse(input);
  if (!parsed.success) return { ok: false, error: { code: "invalid_input", issues: parsed.error.issues } };

  const supabase = await createServerClient();
  // ... insert, idempotent on client_id, write audit_log
  return { ok: true, data: { id } };
}
```

Checklist:

- [ ] First lines: `"use server"` and `import "server-only"`.
- [ ] Validates input with the domain Zod schema. Never trusts the client.
- [ ] Returns `ActionResult<T>` (`{ ok: true, data } | { ok: false, error }`). It doesn't throw for expected failures.
- [ ] Uses the user-scoped Supabase client (RLS applies). Service role only in `src/server/services/` with a comment explaining why.
- [ ] Integration test against local Supabase.

### 3.3 Route Handler (HTTP API)

Owner: Claude Code. Location: `src/app/api/<resource>/route.ts`.

Checklist:

- [ ] Exports only HTTP method functions (`POST`, `GET`).
- [ ] Authenticates first (session or API token), then validates the body with Zod, then calls a `src/server/services/` function. Keep business logic out of `route.ts`.
- [ ] Returns JSON `{ error: { code, message } }` with correct status codes (400/401/403/409/422/500).
- [ ] Never logs request bodies that contain money notes, tokens or receipts.
- [ ] Documented in `docs/architecture/api.md`.

### 3.4 Page / screen

Owner: Antigravity. Location: `src/app/(app)/<route>/page.tsx`.

```text
src/app/(app)/transactions/
├── page.tsx         # Server Component: fetch via src/server/queries, render feature component
├── loading.tsx      # Skeleton
├── error.tsx        # "use client" error boundary
└── [id]/page.tsx    # Detail/edit
```

Checklist:

- [ ] `page.tsx` stays thin: it fetches data and renders `<TransactionsScreen />` from `src/components/transactions/`.
- [ ] `loading.tsx` and `error.tsx` exist. Empty state handled in the feature component.
- [ ] Route segment names are English kebab-case (`/month-close`, not `/chot-thang`). UI text is Vietnamese.
- [ ] Works at 390×844; screenshots saved per §2.

### 3.5 Feature component

Owner: Antigravity. Location: `src/components/<feature>/<component-name>.tsx`.

```tsx
// src/components/quick-add/envelope-chips.tsx
"use client"; // only if it needs state/effects/events

import type { Envelope } from "@/lib/domain";

type EnvelopeChipsProps = {
  envelopes: Envelope[];
  selectedId: string | null;
  onSelect: (id: string) => void;
};

export function EnvelopeChips({ envelopes, selectedId, onSelect }: EnvelopeChipsProps) {
  // ...
}
```

Checklist:

- [ ] Server Component by default; `"use client"` only on interactive leaves.
- [ ] Props type named `<Component>Props`, declared in the same file.
- [ ] Domain types from `@/lib/domain`. No money arithmetic, only `formatVnd()` for display.
- [ ] Tap targets ≥ 44px, labels on inputs, `inputMode="numeric"` for amounts.

### 3.6 shadcn/ui primitive

Run `pnpm dlx shadcn@latest add <component>`. The file lands in `src/components/ui/`. Commit it unchanged in its own commit: `build(ui): add shadcn <component>`. Later edits are allowed but must be minimal and explained in the PR.

### 3.7 Hook

Location: `src/hooks/use-<name>.ts` for shared hooks, or `src/components/<feature>/use-<name>.ts` when used by one feature only. Client-only (`"use client"` is implied by consumers). Hooks contain no money arithmetic.

### 3.8 Database migration

Owner: Claude Code. **Always** created with the CLI. Never create migration files by hand.

```bash
supabase migration new create_transactions     # → supabase/migrations/20261120093000_create_transactions.sql
```

Name pattern: `<verb>_<object>[_<detail>]`, where verb ∈ `create`, `add`, `alter`, `drop`, `rename`, `backfill`, `enable`.
Examples: `create_transactions`, `add_tags_to_transactions`, `enable_rls_envelopes`, `create_view_v_fund_balance`.

Skeleton and rules: [database.md §3](database.md#3-migration-file-template). After creating it:

- [ ] `supabase db reset` passes.
- [ ] `pnpm db:types` run; `src/lib/db.types.ts` + Zod schemas updated **in the same commit**.
- [ ] pgTAP test added in `supabase/tests/`.
- [ ] PR labelled `db:migration`.

### 3.9 Tests

| Kind | Location | Naming | Runs in |
| --- | --- | --- | --- |
| Unit (Vitest) | Next to the source file | `<file>.test.ts` | `pnpm test`, CI |
| Integration (Vitest + local Supabase) | `src/server/**/<file>.int.test.ts` | `*.int.test.ts` | `pnpm test:int`, CI |
| DB / RLS (pgTAP) | `supabase/tests/` | `NNN_<topic>.test.sql` | `supabase test db`, CI |
| E2E (Playwright, WebKit iPhone) | `tests/e2e/` | `<flow>.spec.ts` | `pnpm test:e2e`, CI |
| Fixtures | `tests/fixtures/<topic>/` | descriptive kebab-case | — |

Test names describe behaviour: `it("rejects a second close of the same month")`.

### 3.10 Environment variable

1. Add to `.env.example` with a placeholder and a one-line comment.
2. Add to the Zod schema in `src/env.ts` (`server` or `client` section).
3. Add to the secrets matrix in [operations/environments.md](../operations/environments.md#2-configuration--secrets).
4. Set it in Vercel (Preview/Production) and in GitHub Environments if CI needs it.
5. Never read `process.env` directly elsewhere. Import from `@/env`.

### 3.11 Documentation

| Creating | Location | Recipe |
| --- | --- | --- |
| ADR | `docs/adr/NNNN-<title>.md` | Copy `docs/adr/template.md`, next free number, add to `docs/adr/README.md` index |
| Guide (how-to) | `docs/guides/<topic>.md` | Start with "Goal / Prerequisites / Steps / Troubleshooting" |
| Architecture doc | `docs/architecture/<topic>.md` | Mermaid diagrams inline; link the related ADRs |
| Runbook | `docs/operations/<topic>.md` | "When to use / Steps / Verify / Rollback" |
| Screenshot | `docs/screens/` | PNG, 390×844 (or 1170×2532 device), seed data only |

Then add the new doc to `docs/README.md`. Details: [documentation.md](documentation.md).

### 3.12 Sensitive fixtures (MoMo receipts)

Location: `tests/fixtures/receipts/<nn>-<kind>.txt` (OCR text) or `.png`.
Before committing, redact: phone numbers → `09xxxxxxxx`, account numbers → `xxxx`, recipient names → `NGUYEN VAN A`, transaction IDs → random digits of the same length. Add a line to `tests/fixtures/receipts/README.md` saying who redacted it and when. **This repo is public.**

## 4. Files that must never be committed

Enforced by `.gitignore` and GitHub push protection:

- `.env`, `.env.local`, `.env.*.local`, any file containing a real key or token
- `supabase/.temp/`, `supabase/.branches/`, database dumps (`*.dump`, `*.sql.gz`)
- `node_modules/`, `.next/`, `coverage/`, `playwright-report/`, `test-results/`
- Real exports of the Google Sheet or any personal financial data
- OS/editor files (`.DS_Store`, `Thumbs.db`); `.vscode/` except `extensions.json` and `settings.json`
